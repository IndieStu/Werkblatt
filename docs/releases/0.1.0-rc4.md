# Werkblatt 0.1.0rc4

Tag: `v0.1.0-rc.4`

Status: Release Candidate für den kontrollierten Single-Tenant-Piloten

## Zweck

RC4 erweitert den Pilotstand um die vereinfachte Pretix-Veranstaltungserstellung,
eine getrennte Ansicht kommender Workshops und die aggregierte Erfassung
offener Werkstätten. Der Stand bleibt ein Single-Tenant-Pilotrelease und ist
kein allgemeiner Hosted-Multi-Tenant-Release.

## Enthaltene Änderungen

- Workshop User, Editors und Organization Admins können aus freigegebenen
  organisationsbezogenen Standards einfache Pretix-Workshops erstellen.
- Der Assistent unterstützt Ort, Fördertext, Kapazität, Kinderanmeldung und
  einen optionalen Anmeldeschluss; komplexere Einstellungen bleiben bewusst
  in Pretix.
- Slugs werden stabil und fortlaufend erzeugt; Erstellungsvorgänge sind lokal
  idempotent abgesichert und werden nicht unkontrolliert wiederholt.
- Zukünftige Workshops sind von der Dokumentationsansicht getrennt und zeigen
  aktive Anmeldungen sowie, sofern verfügbar, die Kapazität.
- Pretix-Workshops verlinken aus Liste und Kalender direkt zur zugehörigen
  Bestellübersicht in Pretix.
- Editors und Organization Admins konfigurieren offene Werkstattreihen;
  Workshop User erfassen einzelne Termine mit aggregierten Gesamt- und
  Geschlechterzahlen ohne Namen und ohne PDF.
- Offene Werkstätten besitzen eine getrennte, filterbare Statistik mit
  CSV-Export.
- Die Verwaltungsübersicht verwendet konsistente, vollständig klickbare
  Karten.

## Update von 0.1.0rc3

RC4 enthält die Datenbankmigrationen `workshops.0005` bis `workshops.0007`.
Vor dem Update müssen Datenbank und private Medien gemeinsam gesichert sowie
der commit-/Image-ID-gebundene Infrastructure-Preflight ausgeführt werden.

Danach wird das neue Image bereitgestellt und vor dem Start des Webcontainers
aus demselben Image ausgeführt:

```bash
python manage.py migrate --noinput
python manage.py check --deploy
```

Im synthetischen beziehungsweise kontrollierten Pilot-Test sind anschließend
mindestens Anmeldung, kommende Workshops, Pretix-Erstellung ohne
Doppelanlage, Erfassung einer offenen Werkstatt und deren Statistik zu prüfen.
Pretix-Token und sonstige Secrets dürfen weder in Git noch in Ausgaben
übernommen werden.

## Rollback

Der RC3-Image-Pin und der unmittelbar vor dem Update erzeugte gemeinsame
Backupstand von Datenbank und privaten Medien bleiben bis zur Abnahme erhalten.
Da RC4 additive Migrationen enthält, darf bei einem notwendigen Rollback nicht
nur das alte Image gestartet werden. Datenbank und private Medien werden
gemeinsam auf den Pre-RC4-Stand zurückgesetzt und anschließend der RC3-Pin
erneut ausgerollt.
